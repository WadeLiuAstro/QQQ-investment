# 监控指标增强区设计规格

> 日期：2026-08-05
> 状态：设计已确认，等待实施计划
> 范围：在不改变现有页面整体设计与正式决策规则的前提下，新增独立的市场监控佐证区。

## 1. 目标与边界

本迭代采用“混合增强版”：复用现有资产和数据源，将 CNN 恐惧贪婪、QQQ/QQQE、板块、波动率及宏观指标整理为更醒目、可折叠、可视化程度更高的监控区，用于辅助理解市场状态。

硬性边界：

- 新区块属于“监控佐证层”，不得修改 `app/services/decision.py`、五档状态、仓位范围、定投倍率或规则优先级。
- 不新增资产代码和外部数据源；Yahoo 继续复用当前 QQQ、QQQE、XLK、SMH、XLE、XLF、VIX、VIX3M、10 年美债收益率和美元指数日线。
- CNN 当前总分的抓取与含义保持不变，只增量解析端点实际提供的可选历史序列和七项分因子。
- 不连接券商、不保存个人资产、不生成新的买卖指令或综合交易评分。
- 保持当前深色投研终端、涨绿 `#3DDC97`、跌红 `#F0656B`、卡片边框和字体体系，不重构其它页面区域。

## 2. 页面位置与信息层级

采用已确认的 B 方案。页面阅读顺序为：

1. 正式状态、仓位和定投倍率；
2. `^IXIC` 日 K；
3. QQQ 核心卡与宏观流动性卡；
4. 新增“市场监控摘要”区；
5. 事件、信号拆解及其余原有卡片。

监控区顶部始终显示四张摘要卡：

- CNN 市场情绪；
- QQQ 核心趋势；
- QQQE 相对 QQQ 的市场宽度；
- VIX/VIX3M 波动率体制。

摘要下方为四个可点击分组卡：

1. **情绪与波动**：CNN 当前值、历史对比、近一年趋势、七项分因子、VIX 与 VIX3M；
2. **核心趋势与宽度**：QQQ、QQQE、MA200、回撤、5/20 日收益及相对强弱；
3. **成长与板块轮动**：XLK、SMH、XLE、XLF 的日涨跌、5 日方向、20 日动量和成交量状态；
4. **宏观与防御背景**：10 年美债收益率、美元指数及临近的高影响事件。

初始状态下四组全部收起。点击整张分组卡展开，再次点击收起；同一时间最多展开一组。展开状态仅写入浏览器 `sessionStorage`，不上传、不入库，关闭标签页后失效。

## 3. 展开态设计

“情绪与波动”展开后按以下顺序展示：

1. CNN 半圆仪表、当前分数、中文状态、数据日期和可用性；
2. 上一交易日、一周前、一月前、一年前的历史对比；
3. 近一年情绪趋势线；
4. CNN 七项分因子横向信息条：市场动量、股价强度、市场宽度、期权情绪、市场波动率、垃圾债需求、避险需求；
5. VIX 当前值与 5 日方向、VIX/VIX3M 比值及期限结构状态。

其它分组使用同一交互骨架，内部按资产行展示最新值和变化。展开内容不依赖悬停；移动端隐藏次要说明列，但保留指标名、最新值、变化、方向和数据状态。

CNN 从原“信号拆解”的辅助说明中移到新监控区，避免重复。正式风险规则需要的 VIX 当前值仍保留在信号拆解中；新监控区侧重 VIX 的变化方向和期限结构。

## 4. 统一数据口径

所有可比较指标采用“最新值 + 短期变化 + 中期趋势”口径：

- `current`：最新有效值；
- `change_1d`：相对上一交易日的绝对或百分比变化；
- `direction_5d`：近 5 个交易日的 `rising`、`falling` 或 `flat`；
- `momentum_20d`：近 20 个交易日的收益率或变化幅度；
- `as_of`：指标对应的数据日期；
- `available`、`stale`、`note`：可用性、过期状态和说明。

不适用的字段必须为 `null`，前端显示 `--` 或明确说明，不得以零代替缺失值。

配色按指标语义而非数值正负机械处理：资产上涨为绿、下跌为红；VIX 上升代表风险升温，使用红色；CNN 按恐惧—中性—贪婪区间着色，不把分数上升直接解释为利好。

## 5. 数据契约与职责

在 `DashboardPayload` 增加可选顶层字段 `monitoring`，旧快照没有该字段时隐藏新区块。建议结构为：

```text
monitoring
├── generated_at
├── summary[]
└── groups
    ├── sentiment_volatility
    ├── core_breadth
    ├── sector_rotation
    └── macro_defensive
```

每个 summary 和 group 提供稳定的 `key`、中文 `label`、展示状态、数据状态及指标列表。展示状态只描述“上行、下行、平稳、宽度观察、期限倒挂”等事实，不输出加仓或减仓建议。

后端职责：

- 新增 `app/services/monitoring.py`，负责统一变化计算、四组组装、摘要标签和部分缺失状态；
- `app/providers/yahoo.py` 保持现有抓取接口与 NaN/MultiIndex 防护；
- `app/providers/cnn_fear_greed.py` 在现有 `FearGreedReading` 上增加可选历史与因子字段，未知或缺失字段不导致总分不可用；
- `app/scheduler.py` 在已有 bars 和 events 上调用 monitoring 服务，将结果附加到 payload，但绝不传入 `evaluate_decision()`；
- `app/models.py` 为 monitoring 契约增加可选、可验证的 Pydantic 模型。

前端职责：

- `static/index.html` 只新增监控区容器，不重排其它卡片内部结构；
- `static/assets/app.js` 增加独立的摘要、分组、CNN 展开态和资产行渲染函数；
- 前端只格式化和展示 payload，不重新计算指标、标签或综合状态；
- `static/assets/style.css` 增加命名隔离的 monitoring 样式和移动端断点。

## 6. 降级与兼容

- 任一监控组失败不得影响正式 decision、其它 market 卡或页面加载。
- CNN 总分、历史、趋势和七因子分别判断可用性；只有总分时仍展示仪表，其余子区域显示“不可用”。
- 单个 Yahoo 资产失败只降级对应行；若沿用最近有效数据，必须显示原数据日期和“过期”。
- 摘要缺少必要输入时显示“部分数据缺失”，不根据残缺输入生成方向或状态标签。
- 旧 payload 无 `monitoring`、新 payload 部分缺字段、全部监控数据不可用三种情况均须有静态契约测试。
- 页面不得通过其它指标推算 CNN 分因子，不得伪造历史点或实时性。

## 7. 响应式与可访问性

- 桌面端摘要为四列；分组展开使用仪表/趋势/信息条的宽布局。
- 手机端摘要为 2×2；资产行压缩为“名称、最新值、变化/方向、状态”，说明文字换行或隐藏。
- 分组标题使用原生按钮语义，支持键盘 Enter/Space，设置 `aria-expanded` 和关联内容 ID。
- 颜色之外同时使用文字、箭头或状态标签表达变化，避免仅凭颜色传递结论。

## 8. 测试与验收

实施严格遵循 TDD：先写失败测试，再做最小实现。测试范围：

- monitoring 服务的最新值、1 日变化、5 日方向、20 日趋势、分组和摘要；
- CNN 当前总分、可选历史/七因子、字段缺失、HTTP 418 和解析失败；
- scheduler payload 集成、单来源失败、旧快照兼容和 stale 标记；
- HTML 容器、渲染函数、手风琴互斥、`sessionStorage`、无 monitoring 隐藏；
- 桌面四列、手机 2×2、移动端信息保留和无悬停依赖的静态契约；
- 现有五档决策测试保持完全不变。

验收时运行全量 pytest（当前基线 186 项）、生成真实快照，并在桌面和手机断点核验展开/收起、部分缺失、过期和全部不可用状态。完成后同步 `docs/product-roadmap.md`、`CONTEXT.md`、`MEMORY.md`。

## 9. 实施协作约定

- 详细实施计划由 `gpt-5.6-sol` 生成或复核，最多使用 1 个规划子代理；
- 代码执行由 `gpt-5.6-terra` 完成，最多同时使用 2 个、且仅拆分无共享写入冲突的子任务；
- 主代理负责文件边界、TDD 顺序、集成、全量测试、浏览器核验和文档同步；
- 任何规则、阈值、仓位或定投倍率变更均不在本迭代范围内。
