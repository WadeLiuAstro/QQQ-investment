# QQQ 定投与仓位决策仪表盘：设计规格

## 1. 目标与范围

构建一个供个人研究使用的、移动端友好的美股市场监控仪表盘。第一阶段只辅助 QQQ 的持续定投和仓位节奏判断，回答三个问题：

1. 当前应处于哪一个 QQQ 建议仓位区间？
2. 今日相对常规定投应使用多少倍率？
3. 是否存在需要暂停定投或考虑减仓的多重风险信号？

系统只提供透明、可复核的规则化研究结论，不连接券商、不记录个人资产、不自动交易，也不构成投资建议。

## 2. 已确认的用户决策

- 产品路线：先做大盘仓位决策；个股研究、新闻摘要和选股属于后续阶段。
- 交易标的：只围绕 QQQ。
- 操作方式：长期底仓加波段仓位；持续定投，允许每日调整节奏。
- 建议范围：最低 20%、常态 40%、最高 60% QQQ 仓位。
- 输出形式：同时展示原始数据/信号，以及建议仓位区间与定投倍率。
- 减仓规则：普通偏空时减少或暂停后续定投；只有强烈风险时才提示考虑卖出已有 QQQ。
- 个人数据：首期不记录持仓、现金或券商信息。
- 辅助数据：保留板块 ETF；移除 13F 和 ETF 资金流估算。
- 事件：保留 FOMC、CPI、非农等已排期的宏观事件；首期不抓取或总结实时新闻。
- 验证：开发阶段完成历史回测，并在首页展示简要结果。
- 部署：本地完整运行，同时生成免费、可在手机查看的静态版本。
- 视觉：深色交易终端风格，参考 Bloomberg Terminal / TradingView 的克制和高信息密度。

## 3. 总体架构

一个 Python 分析核心服务于本地仪表盘、静态发布和回测，避免三套口径分叉。

| 模块 | 职责 |
| --- | --- |
| 采集器 | 获取市场、情绪和官方事件数据；执行超时、重试和限流保护。 |
| 数据存储 | 本地 SQLite 保存历史行情、最近成功快照和抓取状态。 |
| 指标引擎 | 从价格序列计算 RSI、均线、回撤、成交量异常等。 |
| 决策引擎 | 根据配置化规则输出市场状态、仓位区间、定投倍率和理由。 |
| 回测引擎 | 使用同一指标与决策引擎验证历史表现，防止未来函数。 |
| 本地服务 | FastAPI 提供本地 API 与前端页面，支持手动刷新和完整详情。 |
| 静态导出器 | 输出不含个人信息的 JSON 与静态前端，供手机网页读取。 |
| 自动发布 | GitHub Actions 在交易时段运行采集/计算/导出；开市判断由纽约交易所日历完成。 |

本地模式使用 FastAPI + SQLite + APScheduler。静态模式不依赖常驻免费服务器：计划任务更新 JSON 后发布静态页面。公开发布仅包含通用市场数据和规则结论；本地模式始终保留。

## 4. 数据与时效

| 类别 | 首选来源 | 用途 | 失败处理 |
| --- | --- | --- | --- |
| QQQ、XLK、SMH、XLE、XLF、VIX、10 年美债、美元指数 | yfinance / Yahoo Finance | 行情、走势、技术指标与宏观背景 | 使用最近一次有效快照并标注过期。 |
| CNN 恐贪指数 | CNN 公共网页数据端点 | 情绪确认 | 标为不可用，并从本次评分中排除。 |
| FOMC | Federal Reserve 官方日历 | 事件风险提示 | 显示最近缓存及时间戳。 |
| CPI、非农 | BLS 官方日历 | 事件风险提示 | 显示最近缓存及时间戳。 |

所有行情数据均为尽力而为、个人研究用途。系统显示“生成时间”“来源状态”“盘中估算/收盘正式”三个字段，绝不将延迟数据伪装成实时数据。

日线 RSI 计算不依赖外部预计算指标：使用 QQQ 日线价格在本地计算 Wilder RSI(2) 与 RSI(6)。交易时段用当前价格形成盘中估算值；收盘后重新计算正式值。`RSI(1)` 不纳入实现。

历史估值锚点保留为可编辑配置，但每一项必须附带来源、计算口径和更新时间。估值只做背景参考，不参与日度仓位评分。

## 5. 决策规则

### 5.1 五级输出

| 状态 | QQQ 建议仓位 | 定投倍率 | 默认动作 |
| --- | ---: | ---: | --- |
| 防御 | 20%–30% | 0× | 暂停定投；满足强风险组合时提示考虑减仓。 |
| 谨慎 | 30%–40% | 0.5× | 降低定投。 |
| 中性 | 40% | 1.0× | 按常规定投。 |
| 偏多 | 40%–50% | 1.5× | 适度提高定投。 |
| 加仓机会 | 50%–60% | 2.0× | 提高定投，向仓位上沿靠近。 |

### 5.2 分层判断

1. 长期风险层：QQQ 相对 200 日均线、近期回撤、VIX 水平与变化，决定是否允许进入防御或减仓区间。
2. 短期加仓层：RSI(2)、RSI(6) 的收盘正式值及盘中估算，决定短期定投力度，但不能绕过长期风险层。
3. 情绪和流动性层：恐贪指数、QQQ 异常成交量、10 年美债收益率、美元指数，用于确认压力或机会，不能单独触发交易建议。
4. 板块佐证层：XLK、SMH 用于科技风险偏好确认；XLF、XLE 仅作宏观环境背景，不能机械地将上涨计为 QQQ 利多。

所有阈值、权重和状态映射集中在配置文件。首期采用透明的规则组合，而非黑箱模型；默认值必须经历史回测后再定稿。

### 5.3 防止过度交易

- 页面每 15 分钟刷新，但日度操作信号默认以收盘正式数据为准。
- 盘中只显示估算状态；只有“趋势破坏 + 波动率急升”等多重风险同时满足时，才提示盘中关注风险。
- 一项数据源失败不触发替代性买卖信号；相应理由区明确显示“未参与本次判断”。
- 每个输出必须包含触发项、未触发项和数据时效。

## 6. 页面与视觉

页面为单一只读首页。移动端自上而下：

1. 常驻信号带：市场状态、建议仓位、当日定投倍率、减仓条件。
2. QQQ 核心卡：最新价、日内变化、RSI(2)、RSI(6)、恐贪指数和五日走势。
3. 重大事件卡：未来七天 FOMC、CPI、非农及风险提示。
4. 宏观流动性：VIX、10 年美债、美元指数和迷你趋势图。
5. 板块确认：XLK、SMH、XLE、XLF 的涨跌与五日走势。
6. 信号拆解：趋势、动量、异常成交量、情绪等条件的触发状态。
7. 回测摘要与估值背景：置于低优先级区域。

视觉规范：

- 固定深色主题：基底 `#0A0D12`、卡片 `#12161D`、边框 `#232834`。
- 核心强调色为琥珀金 `#E8A33D`；上涨 `#3DDC97`、下跌 `#F0656B` 仅表达涨跌语义。
- 标题使用 Space Grotesk，正文 IBM Plex Sans，所有数值 IBM Plex Mono 且启用等宽数字。
- 卡片圆角 2–4px、1px 发丝线、无大阴影和渐变卡片。
- 触控目标不小于 44px，文字满足 WCAG AA，对动态效果尊重 `prefers-reduced-motion`。

## 7. 可靠性、测试与验收

### 7.1 容错

- 每个数据源独立抓取、独立状态记录和独立 UI 降级。
- 抓取失败时保留最近一份完整有效快照，显示其生成时间与过期状态。
- 导出 JSON 写入临时文件并原子替换，避免静态页面读到半写入数据。
- GitHub Actions 失败时保留上一版已发布静态数据。

### 7.2 自动测试

- RSI(2)/RSI(6) 对固定价格序列的单元测试。
- 每种输入组合到五级状态、仓位区间和定投倍率的单元测试。
- 数据源失败、数据过期、恐贪不可用和事件日历不可用的降级测试。
- 静态 JSON 数据契约测试。
- 回测无未来函数测试：任一交易日只使用当日可得数据。

### 7.3 完成标准

- 本地一条命令启动后可展示全部模块或明确的单卡降级状态。
- 可生成供手机打开的响应式静态页面，且不含个人信息。
- 信号带显示五级状态、建议仓位、定投倍率和可追溯理由。
- 回测可运行并展示累计收益、最大回撤、换手率、状态次数及 40% 定投基准对比。
- README 说明数据局限、部署方式、静态页面公开性和“仅供研究、不构成投资建议”。

## 8. 非目标

- 不接入券商、交易账户、订单或自动下单。
- 不保存个人持仓、现金、成本或身份信息。
- 不实现实时新闻聚合、AI 新闻摘要、推送通知或告警。
- 不实现 13F、ETF 资金流估算、复杂个股研究或选股。
- 不承诺实时行情、信号表现或投资收益。
